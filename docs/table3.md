# 表 3 的结果记录与离线回放

## 从正式试验记录复算

`node scripts/table3.mjs` 读取 `results/table3-counts.csv`。每行给出一个版本、一种请求形状、一个种子和一种模板配置的试验数、违反试验数和请求数。脚本检查 240 个组合是否齐全，按论文列顺序合计基础配置和扩展配置，并与表 3 的三行记录核对。

源实验标识为 `confirmatory-api-v2-20261111`。导出时逐行读取该次运行中 101 至 120 号种子、修复前后两个版本的 40 份 `<version>.cases.jsonl`。每份记录位于 `<run-id>-seed<seed>-<version>` 运行目录。只选取 `phase=strategy` 的正式比较。每组累计行数和 `requests`，将 `pass=false` 的行计为违反试验。一次试验任意字段在 PATCH 和 GET 中均违反，仍只计一次。导出时核对了逐试验的 `checks`、`violations` 和 `pass`，失败检查均为字段值或读回值检查。所有分组计数均与每份运行摘要及整次实验的 `analysis-summary.json` 一致。

| CSV 中的值 | 源记录中的值或含义 |
| --- | --- |
| `legacy`、`fixed` | 修复前、修复后 |
| `single` | `targeted-revision-relations`，只提交一个事实字段 |
| `random` | `uniform-random-valid-patch`，从 11 项事实字段的非空子集中均匀抽样 |
| `full` | `source-guided-full-form-update`，提交全部事实字段，其中一项更正 |
| `base14`、`extension` | 14 个基础模板、1 个扩展模板，每种请求形状每个模板运行 12 次 |

每次试验包含建单、PATCH 和 GET 三次请求。这部分共 21,600 次试验、64,800 次请求。计数范围限于三种形状的主比较。B13 是运行前已知的正控。表 3 计量给定请求形状下的违反次数。不同模板共用同一个被测实现。

公开计数可以逐种子、逐配置复算全表。修复前随机子集在基础配置有 2,945/3,360 次违反，在扩展配置有 211/240 次违反，合计 3,156/3,600（87.67%）。逐请求的报文、逐试验的字段值和校内后端未随包发布。

## 单字段虚构回放

`node scripts/replay.mjs` 从 `examples/one-field.json` 读取建单后的前态、含版本号的实际提交体、假定的 PATCH 响应和假定的随后 GET 响应。地点由模型房间 A 改为 B。`version` 是并发控制元数据，实际提交的事实键只有 `location`。其值按本实验契约去除首尾空白，其余十项期望值取自前态。程序逐字段并列打印前态、期望值和两次观察。随包样例中两组字段核对均为 11/11。

判定函数 `frameChecks`、事实字段表和比较函数摘自该次实验冻结的独立测试预言机 `oracle.mjs`，保留原逻辑。原试验用受控建单输入作为事实基线，用建单返回状态核对版本、路径。此样例将同一虚构前态提供给两处，行使这部分判定逻辑。两个响应独立保存在 JSON 中。可在副本中只改 `getResponse.body.location`，再执行 `node scripts/replay.mjs <副本路径>`。这时 PATCH 仍通过，GET 会报告 `persisted_fact:location` 不匹配，进程返回非零状态。

示例为本次公开整理新写的观察值，未计入表 3。整个回放在本地读取文件，无需网络。回放验证期望值构造、响应比对和读回比对。请求数沿用示例的三步约定。回放结果只反映所给的两份观察，真实后端的处理和持久化需要另行实测。
